## 2024-04-19 - WeChat Mini Program Performance Pattern: Avoid redundant setData for array length
**Learning:** Setting derived state (like array length) inside a component property's observer using `setData` triggers redundant secondary render cycles, which degrades performance. However, removing derived state must be handled carefully: if a variable is used inside a `<template>`, it must be explicitly passed via the `data` attribute (e.g., `data="{{...item, listLength: list.length}}"`) to avoid scope regressions. Additionally, if the component's initial data block has a default value for the removed derived state (e.g., `listLength: 1`), it should be preserved if it acts as a UI hack to prevent empty-state flashing prior to asynchronous data loading.
**Action:** Compute and use derived state directly in WXML templates (e.g., `{{list.length}}`) or pass it as computed inline properties rather than using `setData` in observers. When refactoring these, verify template scope requirements and initial empty-state visual behavior.
