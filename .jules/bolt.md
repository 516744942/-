## 2024-05-18 - [Redundant setData in Observers]
**Learning:** Found a common performance bottleneck specific to this codebase architecture: using `setData` inside component property observers to set derived state (like array lengths). This causes redundant, expensive secondary render cycles because data is unnecessarily serialized across the logical and rendering layers.
**Action:** When finding derived states, avoid `setData` in observers entirely if possible, either by computing values directly in WXML or by passing derived variables as computed inline properties in templates (e.g., `data="{{listLength: list.length}}"`). If `setData` cannot be avoided, guard it with strict equality and null checks (e.g., `if (newVal && this.data.listLength !== newVal.length)`) to prevent unnecessary trigger renders.
