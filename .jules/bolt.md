## 2024-04-07 - Avoid Redundant setData in WeChat Mini Program Component Observers
**Learning:** Setting derived component state (like array lengths) inside property `observer` callbacks using `setData` is an anti-pattern. Every call to `setData` triggers a synchronous render cycle. Since the property update itself will trigger a render, modifying state in the observer causes an unnecessary secondary render cycle, leading to performance bottlenecks, especially in components rendered often like `courselist` and `rowscroll`.
**Action:** When derived state from properties is needed in WXML, compute it directly within the WXML expressions (e.g., `wx:if="{{list.length!=0}}"`) instead of saving it in `data`. If derived state must be passed to nested templates, evaluate it inline when invoking the template (e.g., `<template data="{{...item, listLength: list.length}}">`).
