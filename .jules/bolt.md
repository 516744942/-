
## 2024-05-18 - Minimize Redundant `setData` in WeChat Mini Program Components
**Learning:** In WeChat Mini Programs, setting derived state (like array lengths) inside property `observer`s using `setData` triggers redundant secondary render cycles, impacting performance. Sometimes, the `setData` can be entirely replaced by computing the derived state directly in WXML or in template attributes (e.g., `data="{{...item, listLength: list.length}}"`). When an explicit `setData` cannot be fully removed (such as when a default state `data: { listLength: 1 }` is used as a UI hack to prevent empty-state flashing prior to async loading), wrapping the `setData` call with a strict equality check (`if (this.data.listLength !== newVal.length)`) prevents redundant render cycles when object references update but the primitive derived values do not.
**Action:** When updating WeChat Mini Program properties with derived values, preferentially pass the computed values directly in WXML bindings. If `setData` is required for edge cases, always safeguard the call with an equality check against the current primitive value.
