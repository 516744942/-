## 2024-06-18 - WeChat Mini Program Performance Optimization
**Learning:** In WeChat Mini Programs, setting derived state like `listLength: newVal.length` inside an `observer` triggers redundant re-renders via `setData`. A better approach is to pass this state inline using standard wxml data-binding or explicitly compute it in a template context if required, removing the `setData` call from the `observer` to improve performance. However, if the `listLength` property provides a default like `1` as a UI hack to prevent empty-state flashing prior to async loading, removing `setData` inside `observer` must be handled properly, or the default `1` will cause a UI bug later by retaining its initial value even when data is empty. Thus we need to explicitly compute it in the template or bind it, and remove the data object reference or wrap the `setData` in a conditional check `if (newVal && this.data.listLength !== newVal.length)` to avoid unnecessary renders when object references update.
**Action:** Wrap the `setData` in `if (newVal && this.data.listLength !== newVal.length)` to prevent unnecessary renders in `components/courselist/courselist.js` and `components/rowscroll/rowscroll.js`.
