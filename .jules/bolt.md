## 2024-05-24 - Unnecessary setData in Component Observers
**Learning:** In WeChat Mini Program, calling `setData` inside an observer (especially to set derived state like `list.length`) causes unnecessary secondary render cycles. Derived state can either be computed directly in WXML (e.g. `{{list.length}}`) or passed via a `data="{{listLength: list.length}}"` attribute to a template without triggering an extra `setData` update. Furthermore, for observers that MUST do `setData` (e.g. on `courselist.js`), adding an equality check (e.g. `if (newVal && this.data.listLength !== newVal.length)`) prevents redundant renders when the array reference changes but the length doesn't.
**Action:** Always check `observer` functions for derived state calculations that use `setData`. If the computed value is only needed in the template, compute it inline or strictly guard the `setData` call to avoid redundant updates.
