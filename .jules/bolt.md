## 2024-05-24 - Avoid `setData` in property `observer` for derived state
**Learning:** Using `setData` inside an `observer` function of a component property (like `list`) to update derived state (like `listLength`) triggers redundant secondary render cycles in WeChat Mini Programs. Sometimes we can remove it entirely and compute the state inline in WXML templates (e.g., `listLength: list.length`). However, when initial state like `listLength: 1` is used as a UI hack to prevent empty-state flashing prior to data loading, it cannot be cleanly removed.
**Action:** For derived states that can be computed inline, pass them via WXML (e.g., `data="{{listLength: list.length}}"`) and remove the `setData` from the observer. If default state preservation is required, compute a fallback value and wrap the `setData` call in a strict equality check (`if (this.data.listLength !== newLength)`) to prevent unnecessary renders when properties are updated but the derived length doesn't change.
